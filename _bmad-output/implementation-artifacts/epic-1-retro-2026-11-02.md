### Spec-to-implementation reconciliation

- **F1. Sprint status drifted from spec status.** `sprint-status.yaml:34-37` says `review` for 1-2..1-5, while `spec-1-2..1-5` have `status: 'done'`. The 1-6 review noted it and rejected it as "false" (`spec-1-6-token-guard-script.md`, Rejected list: "Spec `done` while sprint status says `review`"). It is true and it blocks the machine verdict. Disposition: **fix now** (A1). Prevention: the review step that sets a spec to `done` should also sync sprint status.
- **F2. Epic 1 ACs are met on the evidence.** Core is untouched (`git diff --stat 43697ff^..8067e1f -- Packages` is empty; only `project.yml` changed, +17 lines for the test target). App Swift Testing: 21 tests in 5 suites pass. Core: 187 tests pass. `swiftlint`: 0 violations in 73 files. `scripts/check-tokens.sh` exits 0 on the clean tree. `scripts/test-check-tokens.sh`: ALL TESTS PASSED. Gallery and base components exist in `App/Design/` (14 files, none over 92 lines). Disposition: accept.
- **F3. Story 1.6 AC "the list is documented in `CLAUDE.md` Commands" is met only partly.** `CLAUDE.md:31-32` and the paragraph under Commands name the script, the test script and `scripts/token-guard-paths.txt`. They do not say when to run the guard or what the exit codes mean (deferred in `deferred-work.md`, review of 1-6). Disposition: **fix now** (A2).

### Duplication map / pattern divergence

- **F4. The guard does not cover the epic's own mapping file.** `scripts/token-guard-paths.txt` lists only `App/Design`. `App/Support/CategoryTone.swift:16-17` keeps eight hex literals as mapping keys, and `deferred-work.md` (review of 1-1) said "the Story 1.6 guard script must migrate or allow-list `coreDefaults`". Nothing records which was chosen. The file is unguarded, not allow-listed. Disposition: **defer to Epic 2 start** with a decision (A3), since the choice is between a skip-by-name rule like `ColorToken.swift` and moving the hex keys into the token layer.
- **F5. Known bypasses in the guard.** Recorded in `deferred-work.md` (review of 1-6): `.green`, `.gray`, `.yellow`, `.purple`, implicit `.accentColor`, `Color(red:green:blue:)`, `0x` integers, 3- and 8-digit hex, `NSColor.red`, `.systemBlue`, `.font(.system(` split across lines. My scan of unmigrated code confirms they matter for the next epics: `App/Support/Color+Hex.swift:8,22` uses `.gray`, `App/Journal/JournalEntriesView.swift:152` uses `Color.accentColor`, `App/Palette/PaletteView.swift:45,118` uses `.system(size: 22)`, `Color.red`, `Color.orange`. `.gray` in `Color+Hex.swift` would pass the guard today. Disposition: **fix now before the first screen enters the list** (A3). Prevention: a guard is only as strong as its pattern list; widen it before each epic that adds screens, with a fixture seen failing first.
- **F6. No duplicated logic found.** Tone hexes live only in the token layer (`ColorToken.swift`); `CategoryTone.swift` keeps only the Core default hexes as mapping keys. Checked by grep over `App/`, not by script. Disposition: accept.
