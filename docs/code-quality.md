# Оценка качества кода (версия 0.1.1)

Это самопроверка: код писал и оценивает один и тот же автор (Claude), поэтому слепые зоны у них общие. Независимое ревью ветки не проводилось. Оценка опирается на проверяемые факты (команды в конце), а не на впечатления. Против актуальных рекомендаций Apple по SwiftUI/SwiftData код отдельно не сверялся.

**Вердикт.** Для личного инструмента версии 0.1 код хороший: ядро выше среднего, оболочка приложения нормальная, но с шероховатостями. Для данных, которые вы собираетесь копить годами, есть два риска, которые стоит закрыть до того, как накопится история (раздел «Важнее всего»).

## Важнее всего (стоит исправить до накопления истории)

1. **Запуск падает без объяснений, миграций нет.** `AppEnvironment.makeStore` при любой ошибке открытия базы вызывает `fatalError`. Схема данных не версионирована (`VersionedSchema`). Если когда-нибудь поменять модели или база повредится, приложение просто не запустится, а восстановить данные будет нечем. Исправление: версионировать схему сейчас (пока она маленькая), вместо `fatalError` показывать окно с причиной и путём к файлу, при запуске делать резервную копию базы (последние N штук).
2. **Чтение данных молча проглатывает ошибки.** В хранилище восемь вызовов `(try? context.fetch(...)) ?? []`. Сбой чтения выглядит как «данных нет»: `categories()` вернёт пусто, и приложение заново засеет стартовые категории; `runningEntry()` вернёт `nil`, и можно запустить второй таймер. Вероятность низкая, цена высокая. Исправление: сделать чтения `throws(StoreError)` и показывать ошибку.

## Важно (улучшает надёжность и поддержку)

3. **Логика просочилась во вью**, хотя принцип «UI без логики». `JournalEntriesView` содержит перечисление `Period` и `applyPeriod()` (период → условия фильтра); `CategoriesView` решает, можно ли удалять категорию сразу, и выбирает цвет новой категории (дублируя список цветов палитры). Это не покрыто тестами. Исправление: перенести в `JournalViewModel` и покрыть тестами.
4. **Тексты ошибок для пользователя сырые.** `AppModel.perform` показывает `String(describing: error)`, то есть что-то вроде `noRunningTimer`, хотя готовые русские тексты есть в `StoreError.message`.
5. **Побочные эффекты в `didSet`** — источник бага двойного Enter. Более надёжный стиль: `items` как вычисляемое производное от `input`, а не отдельное состояние, которое надо синхронизировать вызовами `reload()`.
6. **Лишняя нагрузка.** `AppModel` каждую секунду делает запрос к базе и обновляет `now`, даже когда таймер не идёт. Достаточно считать время от `running.start` через `TimelineView` или тикать только при запущенном таймере.
7. **`conflicts` читает всю историю.** Запрос ограничен только сверху (`start < upper`), то есть при каждом старте в память грузятся все прошлые записи. На годы данных это заметно; нужно добавить нижнюю границу.

## Мелочи

- Одно предупреждение компилятора (найдено при этой проверке): в `JournalEntriesView` используется `Timer.publish`, но нет `import Combine`.
- Мёртвый код: `Placeholder.swift` (`TimeTrackerCore.version`) используется только дымовым тестом.
- `activate(ignoringOtherApps:)` формально устарел с macOS 14, но это единственный вариант, который работает на macOS 27 (замер 4 из 4 против 0 из 4). Может перестать работать в будущей версии.
- `AppRouter` — синглтон (делегат AppKit создаётся раньше SwiftUI-приложения, и инъекцию туда не передать). Это осознанный компромисс, но тестировать его труднее.
- Строки интерфейса зашиты на русском (нет String Catalog), аудита доступности не было, заголовок окна настроек английский.
- Нет CI: линтер, тесты и покрытие запускаются только вручную скриптами.
- Слой интерфейса автоматическими тестами не покрыт: он проверяется вручную и временными стендами, которые в репозиторий не входят.
- Часть файлов Muter пропускает из-за собственных ограничений (кириллица, `throws(E) -> T`, многострочные строки); они покрыты ручными мутациями.

## Что не оценивалось

- Производительность на больших объёмах данных (годы записей): не измерялась.
- Совместимость с будущими версиями macOS, кроме 27.
- Поведение при смене часового пояса и при засыпании компьютера с идущим таймером: есть тесты на уровне логики, но не на реальном устройстве.
