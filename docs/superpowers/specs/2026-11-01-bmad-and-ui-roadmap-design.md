# Дорожная карта: BMAD, исправления окон, дизайн-система, публикация

Дата: 2026-11-01. Статус: согласовано в диалоге, ждёт ревью файла.

## Цель

Автор учит Swift и хочет: (1) вести задачи по spec-driven подходу с полным BMAD, (2) понимать каждую строку кода, (3) опубликовать проект на GitHub как первое Swift-приложение.
Конкретные фичи: исправить окна, добавить настраиваемый хоткей журнала, сделать дизайн-систему и внедрить её в UI.

## Принятые решения

| Тема | Решение |
|---|---|
| BMAD | Полный, stable-ветка, версия `bmad-method@6.12.4`, закреплена |
| Модули BMAD | Только `core` и `bmm`. Внешние модули не ставим: установщик клонирует их с GitHub и запускает `npm install` |
| Superpowers | Не удаляем. BMAD ведёт spec, планы и stories. Superpowers остаётся набором навыков (TDD, отладка, ревью) |
| Проверка BMAD | Архив проверен вручную (MIT, нет телеметрии и install-скриптов). Перед установкой: пробный запуск в пустой папке и проверка `removals.txt` |
| Дизайн-система | Автор подбирает сам и присылает материалы по шагам. Этап ждёт их |
| Хоткей журнала | Дефолт ⌃⌥J. Настраивается в Settings рядом с палитрой, строка в popover. Если окно открыто, только выводит его вперёд |
| Порядок | Исправления окон раньше дизайна, чтобы не переделывать дважды |
| Публикация | README и документация на английском и русском, LICENSE MIT |

## Этап 1. Обучение и интеграция BMAD

1. Прочитать `docs.bmad-method.org`: роли, артефакты (PRD, architecture, UX-спека, stories), порядок работы. Объяснить автору через аналогии с TypeScript/React-процессами.
2. Пробная установка в пустой папке вне проекта: `core` + `bmm`. Зафиксировать список созданных файлов.
3. Если проверка чистая, установить в проект, версию закрепить.
4. Обновить `CLAUDE.md`: описать процесс. Правила TDD, `TimeProvider`, Swift 6 остаются.

Готово, когда: BMAD работает в репозитории, автор может объяснить, что идёт за чем.

## Этап 2. Spec и исправление проблем (через BMAD)

- **Журнал.** Сейчас `JournalEntriesView` использует `HSplitView`: список и `detail` с `minWidth`. Без выбора справа маленький `ContentUnavailableView`, при выборе размеры пересчитываются и список «прыгает».
  Цель: список занимает всю высоту, при выборе записи его ширина не меняется. Гипотеза причины: ширины панелей определяются содержимым. Проверить запуском до правки.
- **Popover.** `MenuBarExtra` со стилем `.window`, внутри `padding(16)` и `frame(width: 300)`. На скриншоте видно лишний полупрозрачный фон шире контента. Причину подтвердить запуском.
- **Хоткей журнала.** Повторить паттерн палитры: `KeyboardShortcuts.Name.openJournal` (дефолт ⌃⌥J), `HotkeyService`, второй `Recorder` в `SettingsView`, вторая строка в `MenuBarContent`. Действие: `AppRouter.openJournal()`.
- TDD: логика в `Packages/TimeTrackerCore`, UI только отображает состояние.

Готово, когда: три исправления в `main`, тесты зелёные, проверено запуском и скриншотами.

## Этап 3. Дизайн-система и UI/UX (через BMAD)

- Вход: материалы автора (референсы, цвета, шрифты). Без них этап не начинается.
- BMAD: UX-спека и architecture дизайн-системы (токены, базовые компоненты, правила).
- Внедрение по экранам: popover, палитра, журнал, настройки. Проверка скриншотами.

Готово, когда: единый визуальный язык во всех окнах.
