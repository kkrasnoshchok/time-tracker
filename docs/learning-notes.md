# Swift для JS-разработчика: заметки по задачам

Короткие объяснения новых концепций через аналогии с TypeScript/React. Пополняется после каждой задачи.

## Task 0: пакет и проект
- `Package.swift` = `package.json` + конфиг workspace, `swift test` = `npm test`, `@main` = точка входа приложения.
- XcodeGen: `project.yml` описывает проект текстом вместо бинарного `.xcodeproj` (его мы не коммитим, как `node_modules`).
- `@testable import X` даёт тестам доступ к `internal`-коду модуля; без него видно только `public`.

## Task 1: TimeProvider и TimeSpan
- `struct` это значение: при присваивании копируется (как неизменяемый объект с `Object.freeze`). `class` это ссылка, как обычный объект JS.
- `let` это `const`, `var` это `let`. `Date?` (Optional) это `Date | undefined`, но компилятор заставляет его обработать.
- `throws(TimeSpanError)` это типизированные ошибки: в TS `throw` принимает что угодно, здесь тип ошибки часть сигнатуры.
- `protocol TimeProvider` это TS `interface`. Мы передаём «источник времени» как зависимость, потому что вызов `Date()` внутри логики сделал бы тесты нестабильными (как `Date.now()` без `jest.useFakeTimers`).
- `Sendable` обещает компилятору, что тип можно безопасно передавать между потоками (в JS поток один, поэтому такого понятия нет).
- `Mutex` (в тестовом хелпере) защищает общее изменяемое значение от гонок между потоками.
- Тесты: `@Test` = `it(...)`, `#expect(a == b)` = `expect(a).toBe(b)`, `#expect(throws: E) { ... }` = `expect(() => ...).toThrow(E)`.

## Task 2: PaletteParser
- `enum PaletteParser` без `case` это «пустое» пространство имён со статическими функциями, как модуль с экспортами в TS; создать экземпляр нельзя.
- `enum` с ассоциированными значениями (`case existing(String)`, `case unknown(String)`) это discriminated union: в TS это `{ type: "existing", name: string } | { type: "unknown", word: string }`. `switch` обязан разобрать все варианты.
- `String` в Swift состоит из `Character` (то, что человек видит как один символ), а не из UTF-16 как в JS: `"🔥".count == 1`, а в JS `"🔥".length == 2`.
- `split(whereSeparator:)`, `map`, `prefix`, `dropFirst`, `joined` это те же `split`, `map`, `slice`, `join`, только ленивые и безопасные по границам. `\.isWhitespace` это key path: короткая запись `{ $0.isWhitespace }`.
- `guard let x = ... else { return }` это ранний выход с распаковкой Optional: в TS аналог `if (x == null) return;`, после которого `x` уже не `undefined`.
- Кортеж `(name: String, wordCount: Int)` это лёгкий безымянный объект `{ name, wordCount }` без объявления типа.

## Task 3: модели SwiftData и Store
- `@Model` это макрос: он на этапе компиляции превращает обычный `class` в сущность БД (как декоратор `@Entity` в TypeORM, только без рефлексии в рантайме). Поля с значениями по умолчанию и опциональные связи нужны для совместимости с CloudKit.
- `@MainActor` привязывает класс к главному потоку. В JS поток один, поэтому такого нет; в Swift компилятор проверяет, что вы не трогаете `TimeStore` из фонового потока.
- `class` против `struct`: модели БД это классы (ссылки: два места видят один и тот же объект), а `TimeSpan` из прошлой задачи struct (значение). `===` сравнивает ссылки, как `Object.is`.
- `#Predicate { $0.category?.id == id }` это типобезопасный фильтр запроса. Как `where` в ORM, но компилятор проверяет имена полей.
- `FetchDescriptor` + `context.fetch` это `SELECT`; `context.insert/delete/save` это INSERT/DELETE/COMMIT. Контекст ведёт себя как unit of work в ORM.
- Конфликт имён: `Category` оказался занят типом из Objective-C рантайма, который тянет `Foundation`. В JS таких «скрытых» глобальных имён нет, в Swift при импорте Apple-фреймворков они бывают, поэтому тип назван `EntryCategory`.
- `throws(StoreError)`: функция может бросить только `StoreError`. Системные ошибки (например, неудачное сохранение) мы ловим в `do/catch` и превращаем в `.saveFailed`.

## Task 4: таймер и записи
- `extension TimeStore { ... }` в другом файле дописывает методы к типу, как миксин; удобно, чтобы не раздувать один файл (в TS ближайшая аналогия — declaration merging для классов, но в Swift это обычная практика).
- `guard ... else { throw ... }` в начале функции собирает все проверки сверху («ранний выход»), а изменения данных идут только после них. Поэтому при ошибке ничего не меняется (тест `startBeforeRunningStartThrowsAndKeepsRunningTimer`).
- `var first: TimeStore? = ...; first = nil` освобождает объект: Swift сам считает ссылки (ARC), сборщика мусора нет. Мы так «закрываем» хранилище и проверяем, что таймер пережил перезапуск.
- `try?` превращает ошибку в `nil` (в JS это `try { ... } catch { return undefined }`); `try #require(x)` в тестах бросает ошибку и падает тест, если `x == nil`.
- Замыкание `{ lhs, rhs in ... }` это стрелочная функция; `sorted { ... }` принимает компаратор, как `Array.sort((a,b) => ...)`, но возвращает `Bool` («a раньше b»), а не число.
- `Set.insert(x).inserted` вставляет и сразу сообщает, был ли элемент новым: компактный способ дедупликации в порядке появления.
- Мутационная проверка вручную: мы ломали строку кода и убеждались, что тест краснеет. Если тест не краснеет, он ничего не защищает.
